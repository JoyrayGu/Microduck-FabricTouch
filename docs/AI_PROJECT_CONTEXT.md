# 机器鸭触觉联动项目上下文

最后更新：2026-10-15

## 信息可信度标记

- **[实测确认]**：已经在当前硬件或当前环境中实际验证。
- **[源码确认]**：从当前工作区的源码、脚本或配置中确认，但不等同于当前真机实测。
- **[项目说明]**：由项目成员说明，当前没有独立复核。
- **[待确认]**：证据不足，实装前必须重新检查。

## 项目目标

将柔性触觉织物的压力数据转换为高层触觉事件或手势，并驱动机器鸭执行经过审核的动作。当前先验证同事交接的 Windows + Raspberry Pi 真机链路；后续计划把机器人计算平台迁移到 RK3566，并在 Ubuntu 22.04 上搭建 ROS 2 节点。

- **[项目说明]** 当前阶段暂不讨论或搭建 3D 仿真。
- **[项目说明]** 最终机器人应自带计算主机，不依赖开发电脑持续参与动作控制。
- **[项目说明]** 目标操作系统已经确认为 Ubuntu 22.04。
- **[待确认]** ROS 2 发行版、消息类型、包名、工作区名和部署方式尚未确定。
- **[源码确认]** 尚未创建 ROS 节点、ROS 工作区或 launch 文件。

## 平台演进关系

### 当前真机：Raspberry Pi 交接包

同事交接的两个文件夹是当前真机验证的主要依据。交接包整体功能基本完成，但其中部分动作仍需逐项实机验证。

- **[项目说明]** 当前拿到的机器鸭使用 Raspberry Pi。
- **[源码确认]** Pi 端使用 OpenRB-150 和 Dynamixel SDK 控制 XL330 舵机。
- **[源码确认]** Pi 服务通过 TCP `0.0.0.0:9000` 接收纯文本动作命令。
- **[源码确认]** 服务端配置为 Dynamixel Protocol 2.0、57600 baud，候选 ID 为 `1, 2, 3, 5, 6, 7, 8, 9, 10, 13, 14, 15`。
- **[待确认]** 上述舵机参数是否与当前实物完全一致。

### 历史原型：microduck_skin / microduck_brain

`microduck_brain` 是入职前依据与项目负责人的沟通、在没有真机的条件下借助 Copilot 搭建的原型。它不是当前 Pi 真机配置的权威来源，但其结构化协议和安全边界可以作为后续 ROS 设计参考。

- **[项目说明]** 该原型是在无真机条件下完成的。
- **[源码确认]** brain 文档描述的是 RK3566 / Ubuntu、1 Mbps、ID 1-14 的另一套配置。
- **[待确认]** 原型中的历史“已实机验证”注释不能视为当前机器鸭的验证结果。
- **[长期决策]** 不应直接把原型的舵机 ID、波特率或姿态数据应用到当前 Pi 真机。

### 后续目标：RK3566 + Ubuntu 22.04 + ROS 2

- **[项目说明]** 项目负责人计划后续将 Raspberry Pi 替换为 RK3566。
- **[长期决策]** ROS 2 应处理高层触觉事件或手势，不应允许网络输入直接指定舵机 ID、目标位置、电流或速度。
- **[长期决策]** 机器人端应保留动作白名单、事件校验、互斥、超时和硬件启用开关。
- **[待确认]** RK3566 的具体系统镜像、串口设备、舵机总线配置和 ROS 2 发行版。

## 当前硬件与通信拓扑

当前待验证链路：

```text
柔性触觉织物
  -> Windows USB 串口（9600 baud）
  -> skin_touch_bridge.py 或 skin_duck_gui.py
  -> 局域网 TCP :9000（纯文本命令）
  -> Raspberry Pi / pi_duck_control_server.py
  -> OpenRB-150
  -> XL330 舵机
```

- **[实测确认]** 触觉织物串口波特率为 9600。
- **[源码确认]** Windows 程序默认寻找 USB VID/PID `0483:5740`。
- **[源码确认]** Windows 程序默认连接 `172.20.10.2:9000`；实际 IP 需要现场确认。
- **[项目说明]** 同事表示 Windows 与 Pi 会自动接入同一 Wi-Fi。
- **[待确认]** 自动联网尚未实际验证；交接包源码不负责配置 SSID、密码、NetworkManager、netplan 或 `wpa_supplicant`。
- **[源码确认]** SSH 只用于部署、维护和日志查看，运行时动作链路使用直接 TCP，不使用 SSH 转发。

后续 ROS 目标链路可考虑：

```text
tactile_skin_node
  -> ROS 2 高层手势主题
  -> gesture bridge / action node
  -> 动作白名单和安全状态机
  -> 舵机运行时
```

是否继续复用本机 TCP NDJSON 作为过渡边界，应在 ROS 包设计时决定。

## 触觉数据与触发逻辑

### 同事交接包

- **[源码确认]** 串口帧头为 `0x98`，帧尾为 `0x81`，整帧 2057 字节。
- **[源码确认]** 7 字节头部之后是 2048 字节载荷，每个字节拆成两个 4-bit 值，形成 64 x 64 触觉阵列。
- **[源码确认]** 默认单元阈值 `CELL_MIN=4`，最少活跃单元数 `MIN_ACTIVE=30`。
- **[源码确认]** 按下消抖为 3 帧，释放消抖为 10 帧，最短命令间隔为 3 秒。
- **[源码确认]** 当前触觉桥只发送 `TOUCH\n`，不区分点击、单向抚摸或往返抚摸。
- **[限制]** 厂商 `SerialDataCollection.exe` 与 Python 触觉桥不能同时占用同一 COM 口。

### 历史结构化 skin/brain 原型

- **[源码确认]** 支持 `tap`、`single_stroke`、`back_forth_stroke` 三种高层手势。
- **[源码确认]** 协议为 TCP 长连接上的 UTF-8 NDJSON，版本为 1，默认端口 9000。
- **[源码确认]** 单条事件上限 4096 字节，默认最大事件年龄 2000 ms。
- **[源码确认]** 默认映射为：
  - `tap -> tilt_head`
  - `single_stroke -> tilt_head`
  - `back_forth_stroke -> head_wag`
- **[源码确认]** brain 默认 dry-run，只有显式启用硬件后才写舵机。

## 同事交接包的动作接口

Pi 服务端支持以下命令：

| 命令 | 含义 | 当前状态 |
| --- | --- | --- |
| `PING` | 检查 TCP 服务 | 源码存在，待现场验证 |
| `TILT` | 头部倾斜并回正 | 源码存在，需实机验证 |
| `MOUTH` | 嘴部开合 | 源码存在，需实机验证 |
| `TOUCH` | 组合头部倾斜和嘴部动作 | 源码存在，需实机验证 |
| `STAND` | 站立姿态 | 源码存在，高风险实机验证 |
| `STEP` | 单次迈步 | 源码存在，高风险实机验证 |
| `KNEEL` | 跪姿 | 源码存在，高风险实机验证 |
| `SQUAT` | 下蹲 | 源码存在，高风险实机验证 |
| `LEAN_BACK` | 后仰 | 源码存在，高风险实机验证 |
| `ENABLE` / `DISABLE` | 舵机扭矩控制 | 源码存在，使用前确认语义 |
| `CURRENT <id> <mA>` | 设置单舵机电流 | 源码存在，仅限明确诊断时使用 |
| `CURRENT_ALL <mA>` | 设置全部舵机电流 | 源码存在，仅限明确诊断时使用 |

- **[源码确认]** 服务回复 `OK` 只表示命令被接受，`DONE` 才表示动作函数返回。
- **[源码确认]** `skin_touch_bridge.py` 只读取初始回复，因此它不能证明动作最终成功完成。
- **[源码确认]** 服务启动时会准备 ID 5 和 9；当前实现可能进一步初始化并启用全部候选舵机。
- **[源码确认]** systemd 模板默认设置 `AUTO_TOUCH_INTERVAL_SECONDS=5`，会周期性触发动作。
- **[长期限制]** 初次上机前必须把自动触发间隔设为 `0`，并先进行无动作诊断。

## 关键目录与文件

### 当前真机交接包

- `鸭子机器人联动控制脚本包_20260911/`：同事提供的 Windows + Pi 联动实现。
- `pi_duck_control_server.py`：Pi TCP 服务和 Dynamixel 动作实现。

- `pi-duck-control.service.template`：systemd 服务模板。

交接包部分解压目录名存在乱码，查找文件时应优先按文件名定位，不要依赖乱码路径。

### 历史原型与验证工具

- `microduck_skin/`：触觉采集和结构化机器人手势识别原型。
- `microduck_brain/`：结构化命令服务、安全调度和动作白名单原型。
- `microduck/tools/deployment_validation/`：姿态和部署验证脚本，可作为思路参考，但不能直接假定适用于当前 Pi 真机。

## 长期安全约束

1. 首次连接真机时禁止自动周期动作。
2. 未确认总线参数前，不发送写寄存器、扭矩开启或姿态命令。
3. 先验证通信和状态读取，再验证单个低风险关节，最后验证腿部组合动作。
4. 腿部动作必须在架空、支撑或有人保护的条件下执行。
5. 网络输入只能选择白名单动作，不能直接提交任意舵机参数。
6. 日志中的 `OK`、函数返回或进程未报错都不能替代对实物动作方向、幅度、电流和稳定性的观察。
7. 文档不得保存 Wi-Fi 密码、SSH 密码、私钥、令牌或其他凭据。
8. 当前 Pi 参数与历史 RK3566 原型参数必须分开维护，迁移时重新测量和建档。

## 建议的 ROS 2 设计边界

以下为后续设计方向，不是已经实现的接口：

- 触觉节点发布标准化高层事件，动作节点持有最终控制权。
- 消息至少包含事件 ID、时间戳、手势类型、置信度和可选方向。
- 动作节点实施过期检查、去重、忙碌拒绝、动作超时和急停。
- 初期保留 dry-run，并要求显式启用真机输出。
- ROS 2 发行版应结合 Ubuntu 22.04 的官方支持周期和项目部署要求后确定。
