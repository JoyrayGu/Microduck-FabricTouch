# 电子触觉皮肤 → 鼠标控制器

用《采集设备使用说明-蓝牙_V5.0》里的电子触觉皮肤（压力阵列）**直接控制鼠标**：
移动光标、单击、双击、右键、按住拖拽、双指滚轮。

设备支持 **蓝牙(BLE) 与 USB 两条上行通道**（协议 3.7 的 `0x0D` 指令切换）。
本程序**默认走 USB**：不用配对、插上就用、带宽更大、也没有蓝牙丢包的问题。

协议部分按文档逐字节实现，76 项单元测试全绿（含文档里的全部通讯实例）。

---

## 1. 快速开始

```bash
pip install -r requirements.txt          # USB 只需要 pyserial；蓝牙另需 bleak

python run.py --mock --gui               # ① 没有硬件，先用模拟数据体验全部功能
python run.py --list                     # ② 看看有哪些 USB 串口 / 蓝牙设备可用
python run.py                            # ③ 连真机（默认 USB：自动选口 + 自动试探波特率）
python run.py --gui                      # ④ 带实时压力热力图的界面
```

第一次连真机的推荐姿势（安全）：先只看不动鼠标，确认手势识别对了再开控制。

```bash
python run.py --dry-run --viz            # 只观察：打印压力图和识别结果，不碰鼠标
python run.py --gui                      # 确认没问题后正式接管
```

USB 通道的常用参数：

| 参数 | 作用 |
| --- | --- |
| （不填） | 自动选择 USB 虚拟串口，并自动试探波特率 |
| `--port COM5` | 显式指定串口（跳过自动选口） |
| `--baud 921600` | 显式指定波特率（跳过自动试探，省 1~5 秒） |
| `--usb-port-hint CH340` | 自动选口时按关键字挑（多串口环境下有用） |
| `--usb-format binary` | 设备只发二进制帧时锁定为二进制解析 |
| `--usb-scale 100` | USB 明文（kPa）→ 内部压力单位的换算倍数，默认 100 |
| `--usb-allow-partial` | 允许残缺明文块（缺行按 0 补），默认丢弃 |
| `--usb-no-dtr` | 不置位 DTR（一连上设备就反复重启时试它） |

通用参数：

| 参数 | 作用 |
| --- | --- |
| `--ble --name TT-Skin` | 改用蓝牙通道（按名称或 `--address` 连接） |
| `--dry-run` | 不注入真实鼠标事件，只打印动作（安全调试） |
| `--viz` | 控制台模式下打印压力字符图 |
| `--speed 600` | 光标最大速度（像素/秒），屏幕大就调大 |
| `--mode ninegrid` | 换成九宫格按钮模式 |
| `--duration 10` | 跑 10 秒自动退出（配合自检/脚本） |
| `--save-config my.json` | 退出时保存当前参数 |
| `--config my.json` | 下次直接加载 |
| `--backend null` | 完全禁用鼠标注入（等同 dry-run，但不打印） |
| `--selftest` | 无硬件验收环境：跑通蓝牙/USB 二进制/USB 明文三条链路 |

```bash
python run.py --gui --save-config my.json     # 调好后存下来
python run.py --config my.json --gui          # 下次直接复用
```

## 2. 机器人模式（--robot）：把皮肤当"触觉遥控器"

除了控制鼠标，本程序还能把皮肤当**机器人触觉遥控器**：识别出三种手势，
通过 **TCP 长连接**（换行分隔的 JSON）发给 RK3566 上的
[`microduck_brain`](../microduck_brain)（Duck 机器人的"大脑"），
由大脑驱动头部做拟静力的"卖萌"动作。

```bash
python run.py --robot --mock --brain-dry-run     # 没有硬件 / 没有大脑：只演示，不发包
python run.py --robot --mock --brain-host 192.168.1.50   # 发给真大脑（真联网）
python run.py --robot                            # 用真皮肤（USB）连大脑
```

**手势 → 动作映射**（动作语义完全由大脑决定，皮肤只发手势名）：

| 手势 | 大脑动作 | 说明 |
| --- | --- | --- |
| `tap` | `tilt_head` | 轻点 |
| `single_stroke` | `tilt_head` | 单向划一笔 |
| `back_forth_stroke` | `head_wag` | 来回划（左右摇头） |

常用参数：

| 参数 | 作用 |
| --- | --- |
| `--robot` | 进入机器人模式（**默认 dry-run，不联网**） |
| `--brain-host 192.168.1.50` | 指定大脑地址；**给了它才会真正发包** |
| `--brain-port 9000` | 大脑端口，默认 9000 |
| `--brain-dry-run` | 即使给了地址也**只打印不发送**（联调时用） |

> 安全边界：**皮肤永远只发"手势名"**，绝不发舵机 ID / 数量 / 速度 / 角度。
> 所有安全校验（白名单、去重、时效、单动作互斥）都在大脑端，皮肤的越权输入
> 一律被大脑拒绝。机器人模式**不会注入任何鼠标事件**。

## 3. 两条上行通道

### 3.1 USB（默认）

设备通过 USB 枚举成一个**虚拟串口**（CDC / USB 转串口）。程序会：

1. 枚举本机串口，优先挑选识别到的 USB 转串口芯片（CH340、CP210x、FTDI、STM32 CDC…）；
2. 依次用常见波特率发送一次 `0x0B` 设备信息指令，**谁有应答就用谁**
   （协议文档没有给出 USB 波特率，只能试探；已知参数就用 `--baud` 跳过）；
3. 连接后**先下发 `0x0D = 0x00`**，把上行数据切到 USB。

> ⚠ **为什么每次都要重发 `0x0D`**：文档 3.7 明确写着「该设备已默认蓝牙模式，
> 且掉电重启后自动恢复至蓝牙模式」。所以设备每次上电都会自己切回蓝牙，
> 上位机必须在每次连接时重新下发一次。

USB 通道上会同时出现两类数据，程序自动识别，不需要你手工切换：

| 形态 | 出现场景 | 内容 |
| --- | --- | --- |
| 二进制协议帧 | 连续采集 `0x01`、各类指令应答 | `0x98 … 0x81`，前 2 字节帧号，其后每 2 字节一个点 |
| ASCII 明文块 | 单次采集 `0x02`（文档 3.2 注 2） | 每行 32 个点、空格分隔、3 位小数、共 32 行，**单位 kPa** |

明文块会被自动换算（默认 ×100，见 `--usb-scale`）、自动**重采样**到 `--rows/--cols`
指定的阵列尺寸，然后合成成一条与二进制帧完全等价的采集帧 —— 上层代码对两条通道
是无感的。

### 3.2 蓝牙（`--ble`）

设备出厂默认通道，无需额外参数即可用：

```bash
python run.py --ble --name TT-Skin --gui
python run.py --ble --address AA:BB:CC:DD:EE:FF
```

```
Service         0xFFE0
0xFFE1  Write Without Response   APP -> UART（下行指令）
0xFFE2  Notify                   UART -> APP（上行数据）
```

蓝牙模式下设备发出的通知包**前面有 N 个无效字节**（文档明确提到），程序用
「流式扫描 + 帧头帧尾匹配」处理，无需你操心。

## 4. 手势与映射

| 手势 | 识别条件 | 鼠标动作 |
| --- | --- | --- |
| 移动 | 手指相对落点滑动 | 光标按速度移动（摇杆） |
| 轻点 | 落指后 ≤260 ms 抬起且几乎没动 | 左键单击 |
| 双击 | 两次轻点间隔 ≤420 ms | 左键双击 |
| 长按 | 按住 ≥650 ms 且没移动 | 右键单击（并锁定光标防点歪） |
| 重压拖拽 | 压力超过门限（见下） | 按住左键 + 移动 = 拖拽 |
| 双指同向平移 | 识别到 2 个接触点 | 滚轮（纵向/横向） |

### 启动时是否自动零点校准

默认不自动校准，避免 GUI 一启动就卡在“请勿触碰”的基线采样阶段。
若要在启动时自动进行零点校准，请在配置文件中设置：

- `auto_calibrate_on_start: true`

这会在会话启动后立即执行一次零点校准，并按 `baseline_frames` 采集静置样本。

### 三种映射模式

- **`joystick`（默认，推荐）**：手指相对「零点」的偏移量决定光标**速度**。
  零点默认取**本次落指的起始位置**（`origin=touch`），而不是阵列中心 ——
  这一点很关键：轻点时手指几乎不动，所以光标不会漂，点击非常准；
  要移得远就多滑几下（和笔记本触控板一个手感）。
  想改成「手指停在阵列中心不动」的传统手感，用 `--origin array`。
- **`absolute`**：手指在阵列上的位置直接映射到屏幕坐标。屏幕大、要快速跳转时好用，
  精度受阵列分辨率限制。
- **`ninegrid`**：把阵列划成九宫格 —— 上下左右四边匀速移动，四角是单击/右键/双击/中键，
  中间是「停」。落指即触发，按键式操作。方向移动时还会额外发出 `move_up` / `move_down` /
  `move_left` / `move_right` 这四类独立手势事件，便于 GUI 和日志中直接观察。

### 方向不对？

阵列的行列方向和你的直觉不一致时（比如手指向右滑光标却向上），
在界面上勾选或用参数翻转：`invert_x` / `invert_y`（网格方向，`--flip-x` / `--flip-y`），
以及 `scroll_invert`（滚轮方向）。

### 重压拖拽的门限怎么定（**重要**）

不同通道/模式下的原始压力值量纲不同（蓝牙是 `DATAH*256+DATAL` 的原始计数，
USB 的明文块是 kPa），所以**不要盲信默认值**。程序用了两条判据，取较易满足的一条：

1. **相对判据（默认主用，与量纲无关）**：
   本次接触的压力 ≥ `heavy_auto_ratio`（默认 1.7）× 历史「轻触」压力。
   程序会自动把最近若干次接触的峰值取低分位数当作「轻触」参考值。
   也就是说：**比平时重 70% 就算重压**。
2. **绝对判据**：本次接触的压力 ≥ `heavy_total`（默认 7000）。量纲已知时直接调它最省事。

还有 `heavy_settle_ms`（默认 200 ms）稳定期：落指后的 200 ms 内不判重压，
避免落指的冲击被误判成拖拽。

> 调参方法：跑 `--mock --gui` 或 `--viz` 看「总压力」读数，
> 轻触时大约是多少，把 `heavy_total` 设成它的 1.2~1.5 倍即可。
>
> ⚠ 注意阵列尺寸的影响：`--usb-scale` 与 `resample` 取的是**面积平均**，
> 所以 32×32 的原生阵列降到 7×7 后，整场**求和**只有原来的约 1/21。
> 换阵列尺寸后 `heavy_total` 需要重新整定；相对判据不受影响。

其余关键参数（都能在界面上拖）：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `max_speed_px_s` | 780 | 光标最大速度 |
| `deadzone` | 0.13 | 死区，越大越不容易误动，但起步更「重」 |
| `gamma` | 1.7 | 响应曲线，越大中心附近越细腻、边缘越快 |
| `speed_smoothing` | 0.45 | 速度平滑，抖动大就调小 |
| `pressure_speed_mix` | 0.35 | 按压力度参与调速（轻推慢移、重推快移） |
| `activate_abs` | 300 | 单格压力低于此值视为未接触，需按实测调整 |
| `edge_recenter` | false | 手指顶到阵列边缘后零点自动跟随，可一直平移 |

## 6. 协议实现要点

帧格式（`0x98` … `0x81`）：

```
┌──────┬────────┬────────┬────────┬──────────┬────────┬──────┐
│ 帧头 │  长度  │ 指令位 │ 状态字 │  数据包  │ 校验字 │ 帧尾 │
│ 0x98 │ 2 字节 │ 1 字节 │ 1 字节 │  n 字节  │ 1 字节 │ 0x81 │
└──────┴────────┴────────┴────────┴──────────┴────────┴──────┘
 长度 = 数据包字节数，高位在前
 状态字 = 0x00 上位机下发 / 0x01 设备应答
 校验字 = 帧头~数据包 所有字节之和，高位舍弃（& 0xFF）
```

已实现全部指令：`0x01` 连续采集、`0x02` 单次采集、`0x03` 停止、`0x07` 读电量、
`0x08` 设置阵列、`0x0B` 设备信息、`0x0C` 设置阈值、`0x0D` 发送模式。

`0x0D` 的两个取值（参数帧 1 字节）：

```
01 = 蓝牙发送   98 00 01 0D 00 01 A7 81
00 = USB  发送   98 00 01 0D 00 00 A6 81
```

处理协议里几个容易踩的坑：

1. **蓝牙模式每包前面有 N 个无效字节**（文档明确提到）。因此接收端做的是
   **流式扫描 + 帧头帧尾匹配**，不是按包定长解析。`protocol.scan_frame` 还额外处理了
   「无效数据里恰好出现 `0x98` 伪造出一个大长度、把后面的真帧卡死」的情况：遇到长度
   合法但未收全的候选帧时继续向后找可完整解码的帧，只有后面确实没有时才回到最早的
   候选处等待。
2. **粘包 / 分片**：一帧可能横跨两个通知包，一个包也可能有多帧。
3. **采集数据帧**：前 2 字节是帧号，其后每 2 字节一个点（`DATAH*256+DATAL`），
   行优先排列；帧被截断时补零，保证网格完整。
4. **单帧长度上限**：`MAX_PAYLOAD_LEN` 取 4096。文档 3.2 的 USB 明文块是 32×32，
   转成二进制载荷是 `2 + 1024×2 = 2050` 字节，原来 2048 的上限会把整帧当噪声丢掉。
5. **空载荷的 `0x01/0x02` 帧只是指令应答**（文档 3.1/3.2 的「设备应答 执行成功」），
   不能算作采集数据帧，也不能用来判定「这是二进制通道」。
6. **USB 明文块的解析**（`protocol.AsciiTelemetryParser`）：
   - 以第一行的数字个数为行宽，凑满同样行数即为一块；行宽变化则重新开始；
   - 设备信息等非数字行原样透传，不丢；
   - 容忍行首少量噪声 token。串口在切到明文模式前可能残留半截二进制数据，若因为这
     几个字节丢掉第一行，**每一块都会少一行、后续所有压力场都会垂直错位**；
   - 只交出「凑满」的块：32×32 明文在 115200 波特率下要传 0.6 秒，若按超时结算
     残缺块，很容易在半途切出一块形状错误的压力场。确有需要时用 `--usb-allow-partial`；
   - 行宽与目标阵列不同时按**面积平均**重采样（如 32×32 → 7×7），每格仍是「该位置的
     压力」，因此 `activate_abs` 这类单格阈值与阵列尺寸无关。
7. **USB 通道上的假帧头**：`0x98` 属于不可打印字节，绝不会出现在 ASCII 明文里，
   所以「先找完整帧、帧之前的字节按文本处理」这条规则不会误判；而假帧头只跳过那
   1 个字节，不会连带丢掉紧随其后的明文。
8. 文档 3.4 读取电量应答示例里的校验字印成了 `DE`，按「之前所有字节求和」算应为 `D5`，
   测试用例两种都做了断言（`D5` 通过解析、`DE` 被校验拒绝）。

## 7. 安全设计

- **暂停/急停**：界面上有「暂停控制」和「急停」；`pynput` 已安装时 **全局 Esc** 即急停
  （未安装则窗口聚焦时 Esc 生效）。急停会松开所有按键并复位手势状态。
- **单帧位移限幅**（`max_step_px`，默认 220 px）+ 速度低通，防止某一帧异常把光标甩飞。
- **队列丢弃最旧帧**：上位机处理不过来时不会积压导致延迟越来越大。
- **校准期不动鼠标**：开机 40 帧零点校准期间不产生任何鼠标动作。
- **限幅保护**：`--dry-run` / `--backend null` 可完全不注入鼠标事件。

## 8. 常见问题

**USB 提示「没有找到任何串口」**
① 换根 USB 线（有些线只能充电）、换个 USB 口；② `pip install pyserial`；
③ 到设备管理器确认端口号，然后用 `--port COM5` 显式指定。

**USB 连上了但「总压力」一直是 0**
① 波特率不对 —— 加 `--baud 921600` 或去掉 `--baud` 让它自动试探；
② 端口被别的程序占着（串口助手、厂商上位机）—— 先关掉；
③ 设备反复重启（DTR 接到了复位脚）—— 加 `--usb-no-dtr`；
④ 端口挑错了 —— 加 `--usb-port-hint CH340` 或用 `--port` 明确指定。

**USB 下偶尔提示「明文压力块凑不满（已丢弃 N 块）」**
说明设备实际输出的行数比列数少。加 `--usb-allow-partial` 允许残缺块（缺行按 0 补），
或者把 `--rows` 改成设备实际的输出行数。

**提示「未安装 pyserial」**
```bash
pip install pyserial          # 或者改用蓝牙：python run.py --ble --name <设备名>
```

**光标不动 / 完全没反应**
先看 `--selftest` 是否通过、界面上的「总压力」有没有读数。
读数为 0 说明设备阈值（`0x0C`）设得太高，或 `activate_abs` 太大 ——
用 `--threshold 0` 关掉设备侧阈值试试。

**轻点时光标总在飘**
确认用的是 `origin=touch`（默认）。若仍飘，把 `deadzone` 调大、
`max_speed_px_s` 调小，或开启界面上的空间平滑（`spatial_smooth_passes=1`）。

**点了没反应 / 一次点出两下**
`tap_max_ms` 调大一点（点得慢），或调小（点得快）。双击间隔不合适就改 `double_tap_ms`。

**鼠标事件发不出去、报 `SendInput 失败`**
前台程序以管理员身份运行时，非管理员进程无法向它注入输入。用管理员身份运行本程序即可。

**光标移动不线性、忽快忽慢**
Windows 的「提高指针精确度」（鼠标加速）在起作用。加 `--raw-move` 绕过加速
（改用绝对设置坐标），手感更线性但略「重」。

**没有 tkinter，打不开 `--gui`**
tkinter 是随 Python 一起装的，不能 pip 装。用官方 python.org 安装包或 miniconda 的
Python 即可（控制台模式不需要 tkinter）。

## 9. 扩展

- **换通信方式**：实现 `Transport` 的 `open/send/close` 即可
  （已有 USB / 蓝牙 / 模拟三个实现），上层控制器完全不用改。
  如果新通道也是「字节流」，直接套 `UsbChannelTransport` 就能复用明文块识别、
  重采样与二进制帧扫描，见 `make_transport(..., mock_mode="usb-ascii")` 的用法。
- **换鼠标后端**：实现 `MouseBackend` 的 `_do_move_rel/move_abs/button_down/button_up/scroll`。
- **改映射算法**：`controller.py` 里 `_drive_mouse`（摇杆）、`_drive_absolute`、`_drive_ninegrid`
  三个函数是各自独立的映射入口，加新模式只需再写一个函数并在 `_drive_mouse` 里分发。
- **多指分割**：`features._local_peaks` 用「平台检测 + 最近峰值分配」把接触区域拆成多个
  接触点，比纯连通域更能分开并拢的手指。
