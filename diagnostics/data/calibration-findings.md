# 触觉织物实测结论（里程碑 1 阶段性）

采集时间：2026-10-21
设备：方形标准 skin，USB `0483:5740`，`COM7`，9600 baud
工具：`microduck_skin_diagnostics`

> **2026-10-21 更正**：本文档初版曾断言阵列为「64×64、4-bit」，
> 依据是解包后 `max=15`。经逐字节奇偶性复检，**该结论是错的**。
> 正确结论是 **32×32、每点 16-bit 大端**。第 1、5、7 节已按此改写。
> 详见第 1.1 节的判别证据。

## 1. 已确认的硬件事实

| 项目 | 结论 | 依据 |
|---|---|---|
| 阵列尺寸 | **32×32** | 载荷 2050 字节 = 2（帧号）+ 32×32×2（16-bit） |
| 单元位宽 | **16-bit 大端** | 见 1.1 节奇偶性判别 |
| 单帧长度 | **2057 字节** | 三次采集共 840 帧，全部 2057，`discarded_bytes=0` |
| 帧结构 | `98 ∑LL ∑HH 01 01 <2 字节帧号> <2048 载荷> <cksum> 81` | 实测逐字节一致 |
| 帧率 | **40 Hz 稳定** | 400 帧 / 10.01 s |
| 串口帧同步 | **完全对齐** | Python 按字节流读取时零丢字节；厂商日志中的 2056/999/216 错误源自其自身读取逻辑 |
| 是否需要主动启动 | **需要** | 被动监听 5 秒 `bytes_in=0`；发送 `98 00 00 01 00 99 81` 后才开始推流 |

### 1.1 为什么不是 64×64 / 4-bit（判别证据）

把 2050 字节载荷去掉 2 字节帧号后，对 200 帧 × 1024 字节做逐字节统计：

| 检验 | 结果 | 推论 |
|---|---|---|
| 偶数下标字节的**高**半字节非零次数 | **0 / 204800** | 若为连续 4-bit 打包，此处应大量非零 |
| 偶数下标字节的**低**半字节非零次数 | 7 | — |
| 奇数下标字节的**高**半字节非零次数 | 955 | 奇数位是完整数据字节 |
| 奇数下标字节的**低**半字节非零次数 | 882 | 同上 |

奇偶位置结构差异极大（0 vs 955），排除「每字节拆两个 4-bit 单元」。
按 16-bit **大端**解释时，偶数位是高位字节，实测仅 7 次非零且值全为 1，
说明原始数值基本 < 512，与「低压空闲、轻点几百」的物理量级一致。

初版误判的根源：`max=15` 被当作 4-bit 上限。但在 32×32 的 1024 个点 ×
200 帧上，若各点独立取值 0..15，出现 15 是必然事件，不构成位宽证据。

## 2. 基线（平整、无接触）

| 指标 | 数值 |
|---|---:|
| 非零单元占比 | 0.052% |
| 帧最大值均值 | 3.6 |
| 帧最大值上限 | 8 |
| 活跃单元均值（cell≥1） | 2.1 |
| 出现饱和的单元数 | 0 |

噪声地板约 **0–8**，绝大多数帧最大仅 3–4。

## 3. 织物必须平整

弯折状态（放在桌边下垂）时：

| 指标 | 弯折 | 平整 |
|---|---:|---:|
| 非零单元占比 | 0.672% | 0.052% |
| 帧最大值均值 | 13.81 | 3.6 |
| 活跃单元均值 | 27.5 | 2.1 |
| 饱和单元数 | 42 | 0 |

弯折产生的假信号可达当时位宽上限，足以误判为触摸。**弯折区集中在织物边缘（热点图右下角）。**

## 4. 轻点（4 次）

| 事件 | 持续 | 峰值单元数 | 峰值（16-bit 原始值） |
|---|---:|---:|---:|
| 1 | 0.75 s | 8 | 15（按 64×64 误读） |
| 2 | 0.32 s | 6 | 14（按 64×64 误读） |
| 3 | 0.63 s | 11 | 15（按 64×64 误读） |
| 4 | 0.03 s | 5 | 13（按 64×64 误读） |

> 上表峰值列是初版以 64×64 / 4-bit 误读的产物，**不可用于设定阈值**。
> `run4-tap.bin` 按正确 16-bit 解释的帧峰值为 **263**（单帧最高），
> 有效触碰帧峰值多在 230–260。

同一次点击会因压力短暂回落被切成 4–5 个片段，**释放消抖必须 ≥200 ms** 才能合并。

实测最长一次点击 0.75 s，`microduck_skin` 默认 `tap_max_ms=320` 偏紧。

## 5. 单向滑动（对角线）

- 质心连续移动，持续 2.5 s；
- 滑动时活跃单元仅 3–6 个，远少于轻点的 5–11；
- **阈值偏低时轨迹断裂，偏低才连续可辨**。

说明单一阈值无法同时服务轻点与滑动，需要弱/强双阈值。
具体阈值需按 16-bit 原始量纲重新实测（见第 7 节）。

## 6. 往返滑动

- 去程与回程均可见，回程未回到起点；
- 转向处有约 400 ms 压力空白；
- 有效反转位移远大于默认 `reversal_min_disp=1.2`；
- 对角滑动时 `|Δx|/(|Δx|+|Δy|)` 约 0.47–0.67，默认 `direction_dominance=0.6` 会漏判，应降到约 0.4。

## 7. 待重标的参数

**阵列尺寸无需改动**：`microduck_skin/config.example.json` 的
`device_array: [32,32]` 与实测一致，**保持原值**。

需要重标的只有阈值类参数。`activate_abs: 300` 当前**偏高**：
实测轻点帧峰值约 230–263，300 会挡掉真实轻点。建议先用
`activate_abs: 100` 起步（明显高于噪声地板 8，低于轻点峰值 230），
配合 `activate_rel: 0.12` 按峰值自适应。

```json
"filter": {
  "rows": 32,
  "cols": 32,
  "activate_abs": 100.0,
  "activate_rel": 0.12,
  "min_active_cells": 2,
  "min_contact_cells": 2
},

"robot_gesture": {
  "tap_max_ms": 800,
  "stroke_min_ms": 200,
  "direction_dominance": 0.4
}
```

> 只列 `config.py` 中**真实存在**的字段。`release_debounce_ms` 与
> `tap_min_ms` 在 `RobotGestureConfig` 里并不存在，若要引入需先改代码；
> 当前也没有字段承载「释放消抖」，这解释了为什么一次点击会被切成 4–5 段。

## 8. 数据有效性

| 文件 | 用途 | 是否可用于标定 |
|---|---|---|
| `run1-idle.bin` | 弯折状态基线 | 否（弯折） |
| `run2-flat-idle.bin` | 平整基线 | **是** |
| `run3-baseline.json` | 中间状态（未存 bin） | 否 |
| `run4-tap.bin` | 4 次轻点 | **是** |
| `run5-stroke.bin` | 单向对角滑动 | **是** |
| `run6-backforth.bin` | 往返（结束时未回起点） | 部分可用 |
| `run7-backforth2.bin` | 往返 + 第二指按压织物 | **否**（测试方式造成的双触点，非真实工况） |

run7 说明：因织物未被固定，单指滑动会拖动整块织物，故临时加了第二根手指按压。该场景在最终产品中不出现（织物固定在鸭头），因此不据此调整算法。

## 9. 下一步

1. 物理固定织物（胶带固定四角或防滑垫），使单指可滑动而不拖动；
2. 重新采集一次干净的往返滑动；
3. 按第 7 节参数更新 `microduck_skin` 配置；
4. 打通 `microduck_skin --robot` → `microduck_brain` dry-run；
5. 最后开启真机头部动作（`tilt_head` / `head_wag`）。
